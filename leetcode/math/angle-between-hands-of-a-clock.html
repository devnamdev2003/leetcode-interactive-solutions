Algorithm Logic & Theory

This mathematical algorithm elegantly determines the shortest angle between the hour and minute hands of a standard 12-hour analog clock. It leverages the concept of mapping both hands to the same rotational metric (minutes) to calculate the difference easily.

Mathematical Breakdown:

  • Mapping Hour to Minute Scale: hour = hour * 5
    Instead of working in degrees immediately, the algorithm maps the hour hand's primary position to a "minute" equivalent. For example, 3 o'clock maps to the 15-minute mark.
  • Wrap Around Cases: if (hour == 60) hour = 0;
    12 o'clock maps to 60, but operationally, it starts at the 0 position. The algorithm resets it to 0.
  • Calculating the Degree Difference: abs(((m - hour) * 6) - (m / 2))
    This line is the core engine. Let's break it down:
    • (m - hour) calculates the baseline difference in minutes between the two hands.
    • Multiplying by 6 converts this minute distance into degrees (since 360° / 60 minutes = 6° per minute).
    • However, the hour hand doesn't stay still! It moves slowly as minutes tick by. It moves 30° per hour, which is 0.5° per minute (m / 2). So we subtract the extra drift of the hour hand.
  • Finding the Shortest Angle: Math.min(ans, 360 - ans)
    Two angles are formed by the hands: an interior and an exterior angle, which together add up to 360°. To satisfy the requirement of the "smaller angle", we take the minimum of the calculated angle and its 360° complement.
Time Complexity O(1)

The execution simply performs a constant number of basic arithmetic operations (multiplication, subtraction, absolute value). It does not depend on the size of any input array or loop iterations.

Space Complexity O(1)

The algorithm only allocates a few primitive variables (hour, m, ans) resulting in strictly constant extra space independent of input.
