Algorithm Logic & Theory

This solution implements an efficient iterative search algorithm specifically designed for a Binary Search Tree (BST). It exploits the core property of a BST: for any given node, all elements in its left subtree are smaller, and all elements in its right subtree are larger.

Unique Code Nuance:

Notice that this code uses an elegant while loop with a compound condition: root != null && root.val != val. Instead of maintaining a recursive call stack, it simply updates the root pointer to traverse down the tree. The ternary operator root.val < val ? root.right : root.left efficiently decides the path in a single line.

Core Steps:

  • Step 1: Loop Condition
    Continue traversing as long as we haven't hit a dead end (root != null) and we haven't found the target (root.val != val).
  • Step 2: Traversal Decision
    If the current node's value is less than the target (root.val < val), the target must be in the right subtree, so move root = root.right. Otherwise, move to the left subtree root = root.left.
  • Step 3: Return Result
    The loop exits when either the target is found or we reach a null pointer. Returning root at this point correctly gives the found node or null.
Time Complexity O(H)

Where H is the height of the tree. In the average case (balanced tree), this equates to O(log N). In the worst-case scenario (a skewed tree resembling a linked list), the time complexity degrades to O(N), as it must traverse every node.

Space Complexity O(1)

The auxiliary space is O(1) constant time. Unlike the recursive approach, this iterative version only uses a few pointers to traverse the tree, entirely avoiding the overhead of a recursion call stack.

Algorithm Logic & Theory

This solution implements an efficient recursive search algorithm specifically designed for a Binary Search Tree (BST). It exploits the core property of a BST: for any given node, all elements in its left subtree are smaller, and all elements in its right subtree are larger.

Unique Code Nuance:

Notice that this code uses look-ahead checks: root.left != null && root.val > val. Instead of blindly recursing down and having the base case handle a null node natively at the top of the function, this implementation peeks ahead to ensure a child exists before making the recursive jump. If a child doesn't exist, it bypasses the recursion and falls straight to the final check: root.val == val ? root : null.

Core Steps:

  • Step 1: Check Left Subtree
    If the target value is strictly less than the current node's value (root.val > val) and the left child exists, we recursively search the left subtree.
  • Step 2: Check Right Subtree
    If the target value is strictly greater than the current node's value (root.val < val) and the right child exists, we recursively search the right subtree.
  • Step 3: Base Case & Resolution
    If neither condition is met (either because we reached a leaf node, or the current node matches the target value), we execute the ternary operator: root.val == val ? root : null. This returns the matching node if found, or null to signal an unsuccessful search.
Time Complexity O(H)

Where H is the height of the tree. In the average case (balanced tree), this equates to O(log N). In the worst-case scenario (a skewed tree resembling a linked list), the time complexity degrades to O(N), as it must traverse every node.

Space Complexity O(H)

The auxiliary space is determined by the maximum depth of the implicit recursion call stack. Similar to time complexity, this is O(log N) on average for balanced trees, and up to O(N) for highly unbalanced, skewed trees.
