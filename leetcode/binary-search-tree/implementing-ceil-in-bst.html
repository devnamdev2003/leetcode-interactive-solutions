Algorithm Logic & Theory

The Find Ceil in BST algorithm aims to find the smallest value in a Binary Search Tree (BST) that is greater than or equal to a given target value x. The properties of the BST make this extremely efficient without traversing all nodes.

Core Steps:

  • Initialization:
    We start with a variable c (ceil candidate) initialized to -1. We traverse down the tree starting from the root.
  • Case 1: Exact Match (x == root.data)
    If the current node matches x exactly, it is by definition the ceiling. We immediately return root.data.
  • Case 2: Current node is smaller (x > root.data)
    If the target is larger than the current node, the current node is too small to be the ceiling. Because of BST properties, all nodes in the left subtree are even smaller. Thus, we must move to the right subtree to find a larger value.
  • Case 3: Current node is larger (x < root.data)
    If the target is smaller than the current node, this node is a valid candidate for the ceiling. We update c = root.data. However, there might exist an even smaller valid candidate in the left subtree. So, we continue traversing left to find a "tighter" bound.
Time Complexity O(H)

Where H is the height of the Binary Search Tree. At each step, we move either left or right, discarding half the tree (on average). In the worst case (a skewed tree), $H = N$, yielding $O(N)$. For a balanced BST, $H = \log N$, yielding $O(\log N)$.

Space Complexity O(1)

The provided solution is Iterative. We only use a constant amount of extra space (variables like c and the pointer to traverse down the tree). There is no recursion stack overhead, making the auxiliary space strictly $O(1)$.
