Algorithm Logic & Theory

This solution utilizes a Brute Force (Append & Sort) approach. It is the most intuitive way to merge two arrays into one, taking advantage of the built-in sorting mechanisms in modern languages.

Core Concept: Leverage Built-in Libraries

The nums1 array is guaranteed to have enough space at the end to hold all elements from nums2. Instead of doing a complex merging process, we simply overwrite the empty padding at the end of nums1 with the values of nums2, and then issue a command to sort the entire array.

Execution Steps:

  • Phase 1 - Appending: A pointer i starts at the end of the valid numbers in nums1 (which is index m). A pointer j iterates through nums2. We copy elements from nums2[j] into nums1[i].
  • Phase 2 - Sorting: Once all elements are combined into nums1, we invoke Arrays.sort(nums1). In Java, this typically relies on Dual-Pivot Quicksort or Timsort (depending on data types and internal implementation), which efficiently reorganizes the elements.
Optimization Note: While this is valid, an optimal $O(m+n)$ approach exists using Three Pointers starting from the back of the arrays. The sort approach is slower but easier to write.
Time Complexity O((m+n) log(m+n))

Appending the elements takes $O(n)$ time. However, the dominant operation is the built-in sort function, which dictates an $O(N \log N)$ complexity, where $N$ is the total length $m+n$.

Space Complexity O(1) or O(log(m+n))

Appending is done completely in-place requiring $O(1)$ space. The space complexity heavily depends on the language's internal sorting algorithm. In Java, sorting primitives uses memory on the call stack scaling logarithmically.
