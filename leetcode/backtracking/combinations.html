Algorithm Logic & Theory

This solution uses a highly optimized Backtracking approach to generate all possible combinations of size $k$ from numbers $1 \dots n$. By making a choice (adding a number to the list), exploring all subsequent choices recursively, and then undoing the choice (backtracking), we can exhaustively build valid combinations.

Core Steps & Optimizations:

  • Lexicographical Ordering (No Duplicates):
    To prevent permutations (e.g., [1,2] and [2,1]), the recursion always starts searching from i = start, where the next start is passed as i + 1. This strictly increasing order inherently prevents duplicate sets.
  • Base Case Tracking:
    As soon as current.size() == k, the list is valid. We add a deep copy to our ans list and return immediately, cutting off deeper recursion branches.
  • Boundary Pruning Optimization:
    Instead of iterating i blindly up to n, the loop ends at n - (k - current.size()) + 1.

    Why? If we need 3 more numbers to reach size k, but only 2 numbers are left between i and n, it's mathematically impossible to finish the combination. Pruning these "dead end" branches significantly speeds up execution.
Time Complexity O(k · C(n,k))

Where $C(n,k)$ is the binomial coefficient $\binom{n}{k}$. There are precisely $\binom{n}{k}$ valid combinations. For each valid combination, copying the current list of size $k$ into the answer array takes $O(k)$ time. The boundary pruning ensures we don't spend unnecessary time on invalid branches.

Space Complexity O(k)

Auxiliary space is dominated by the recursion stack and the current list, both of which will grow to a maximum depth/size of $k$. Therefore, auxiliary space is $O(k)$. Note: If we include the space to hold the final output ans, it requires $O(k \cdot \binom{n}{k})$ space.
