Algorithm Logic & Theory

This solution uses a Backtracking (Depth-First Search) approach to systematically explore all possible partitions of a string, returning only those where every substring is a palindrome.

Core Steps:

  • State Definition:
    The recursive function `fun(start)` represents the state where we need to partition the substring `s[start...n-1]`. The `v` list tracks the palindromes chosen so far.
  • Branching (The For-Loop):
    From the `start` index, we loop variable `i` from `start` to `s.length() - 1`. This effectively tests all possible prefixes: `s[start..start]`, `s[start..start+1]`, etc.
  • Pruning & Recursion:
    We only branch further (recurse) if the current prefix `s[start..i]` is a valid palindrome. If it is, we add it to our path `v` and make a recursive call with the new start index: `i + 1`.
  • Backtracking:
    After exploring a branch, we `remove` the last added substring from `v`. This step "undoes" the choice, allowing the algorithm to try the next possible prefix in the loop.
  • Base Case:
    When `start` reaches the end of the string (`s.length()`), it means we have successfully partitioned the entire string into palindromes. We add a copy of `v` to our `ans` list.
Time Complexity O(N · 2^N)

In the worst-case scenario (a string with all identical characters like "aaaa"), there are $2^{N-1}$ possible partitions. For each partition, creating the substring and checking if it is a palindrome takes $O(N)$ time, leading to the overall complexity.

Space Complexity O(N)

The auxiliary space is dominated by the recursion stack and the list `v` used to store the current partition. The maximum depth of the recursion tree is $N$ (when partitioning into single characters), requiring $O(N)$ space. (Excluding space to hold the final answers).
