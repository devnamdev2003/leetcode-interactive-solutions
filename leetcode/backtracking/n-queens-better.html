Algorithm Logic & Theory

This solution uses a highly optimized Backtracking approach combined with HashSets to solve the N-Queens problem efficiently. Standard validation requires scanning the board ($O(N)$), but this method reduces safety checks to $O(1)$ time by leveraging Java's `HashSet` collection.

Core Concepts:

  • Row-by-Row Isolation:
    We only process one row per recursive call. This implicitly guarantees that no two Queens will ever share the same row, removing the need for a "Row HashSet".
  • O(1) HashSet Validation:
    Before placing a Queen at (row, col), we check if the cell is under attack using three sets:
    occupiedCols: Stores column indices currently containing a Queen.
    occupiedDiag1 (row - col): Maps the primary \ diagonal. Any cells on the same \ diagonal will mathematically yield the identical difference row - col. Since this can be negative, a HashSet elegantly handles it without the array indexing adjustments required by boolean arrays.
    occupiedDiag2 (row + col): Maps the secondary / diagonal. Any cells on the same / diagonal will yield the identical sum row + col.
  • Backtracking Phase:
    If placement is safe, we register the `col`, `diag1`, and `diag2` values into their respective HashSets and recursively jump to the next row. Upon returning from the recursion, we backtrack by explicitly removing those values from the Sets, unlocking those attack lines for alternative choices.
Time Complexity O(N!)

Placing the 1st Queen has N options. The 2nd has at most N-1 options, the 3rd at most N-2 options. Although our $O(1)$ HashSets drastically reduce the constant factor compared to scanning loops, the theoretical upper bound of paths explored is inherently factorial $O(N!)$.

Space Complexity O(N)

The auxiliary space scales linearly $O(N)$. The recursion stack will go at most $N$ frames deep. Simultaneously, the three HashSets (`occupiedCols`, `occupiedDiag1`, `occupiedDiag2`) will each store at most $N$ integer elements at any given time.
