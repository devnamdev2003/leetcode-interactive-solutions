Algorithm Logic & Theory

The N-Queens problem asks us to place N chess queens on an N×N chessboard so that no two queens attack each other. This means no two queens can share the same row, column, or diagonal.

This solution leverages a classic Backtracking paradigm combined with HashSets to perform incredibly fast constraint checking.

Core Steps:

  • Row-by-Row Placement:
    We try placing exactly one queen per row. When we are at row, we iterate through every col from 0 to N-1.
  • O(1) Constraint Checking:
    Instead of iterating across the board to see if a spot is safe, we use three Sets to memorize attacked lines:
    • occupiedCols stores which columns have a queen.
    • occupiedDiag1 handles the main diagonals (top-left to bottom-right). Every cell on a specific main diagonal shares the same row - col value.
    • occupiedDiag2 handles the anti-diagonals (top-right to bottom-left). Every cell on a specific anti-diagonal shares the same row + col value.
  • Backtracking (The "Undo"):
    If placing a queen in (row, col) leads to a dead end, we return from the recursion, remove the queen from the board, remove the column and diagonals from our sets, and continue the loop to try the next column.
Time Complexity O(N!)

In the first row, we have N choices. For the second row, we have at most N-1 choices, and so on. This bounds the time complexity to O(N!). The O(1) set lookups drastically reduce the constant factors, making it practically much faster than naive checking.

Space Complexity O(N)

The space complexity is bounded by the recursion stack which can go N levels deep, and the HashSets which each store at most N elements. (Storing the actual N×N board grid requires O(N²) space).
