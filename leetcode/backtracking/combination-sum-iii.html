Algorithm Logic & Theory

This solution uses an exhaustive Backtracking approach to generate all possible combinations of size `k` that sum up to `n`, picking uniquely from digits 1 to 9.

Core Concept: The Take / Skip Paradigm

At every element in the array [1, 2... 9], the recursive function makes a choice to either Take the element (if the target sum remaining is sufficient) or Skip it.

  • Taking the Element: Add the current digit to the combination list v, subtract its value from the remaining target k, and recurse to the next index i+1.
  • Backtracking: Once the recursion returns, we undo the choice. We restore the original target sum k and remove the element from the list v. This allows the algorithm to explore other combinations.
  • Skipping the Element: Without modifying the list v or sum k, we directly recurse to the next index i+1.
  • Base Cases: If we have exhausted all digits (i == 9) OR our combination list has reached the required length (v.size() == len), we stop recursing. If at this point, the list is exactly length len AND the remaining sum k == 0, we have found a valid combination!
Time Complexity O(K · C(9, K))

There are at most 9 choose K combinations to generate. For each valid combination, copying it into the results list takes O(K) time. Because 9 is a small constant, the upper bound is extremely small (C(9,4)=126 combinations), making this effectively O(1) in the grand scheme, but technically proportional to the combination bound.

Space Complexity O(K)

The space complexity is determined by the recursion depth, which is constrained by K (since we stop when v.size() == K). Additionally, the temporary list `v` takes O(K) space. The output list `ans` is not typically counted towards auxiliary space complexity.
