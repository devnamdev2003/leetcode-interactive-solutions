Algorithm Logic & Theory

This solution uses the standard, unoptimized Backtracking approach to solve the N-Queens problem. It places Queens column by column, and checks safety dynamically rather than caching state via arrays.

Core Steps:

  • Step 1: Column-by-Column Placement
    The recursion is structured via fun(m, cl, ans), iterating over exactly one column per depth step. This inherently prevents any two queens from sharing the same column.
  • Step 2: Linear Safety Scan (O(N))
    Before placing a Queen at (i, cl), the isSafe(m, i, cl) function manually scans the board to ensure it's unattacked. Since Queens are only placed in columns 0 to cl-1, it only needs to check the left sides:
    1. Upper-Left Diagonal (\ direction)
    2. Lower-Left Diagonal (/ direction)
    3. Straight Left Row (- direction)
  • Step 3: Branch and Backtrack
    If the cell is safe, place the Queen (m[i][cl] = 1) and recursively jump to the next column. If the recursion finishes, we backtrack by restoring the cell to 0, allowing us to try placing the Queen on the next row of the current column.
Time Complexity O(N! * N)

The backtracking algorithm explores $N!$ possibilities in the worst case. Since verifying whether a queen's position is safe requires an $O(N)$ scan across three linear paths on the board, the overall bound is $O(N! \times N)$. (An optimized approach uses $O(1)$ tracking to achieve $O(N!)$).

Space Complexity O(N²)

The auxiliary space is $O(N^2)$ because we allocate an $N \times N$ integer matrix to represent the board. Additionally, the recursion depth is bounded by $N$, contributing $O(N)$ to the call stack. (Excluding memory needed to store the valid output string configurations).
