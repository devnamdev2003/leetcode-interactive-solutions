Combinations Backtracking Mechanics

This algorithm employs a Binary Inclusion-Exclusion Decision Tree design pattern to assemble all valid subsets of size $k$ from numbers $1$ to $n$. At every level, representing a number $start$, we branch into two possibilities:

The Backtracking Cycle:

  • Decision Branch 1 (Inclusion)
    We insert $start$ into our active `current` list, then advance deep into the subsequent integer options ($start + 1$).
  • Decision Branch 2 (Exclusion & Backtrack)
    Once the left branch resolves, we clean up (backtrack) by removing the last element we added. We then initiate a right branch exploration with $start + 1$ *without* including $start$.
  • Termination Guard (Base Cases)
    When $start > n$, we inspect the size of our accumulated `current` list. If it matches $k$, it represents a valid subset combination, and we clone/append it to our results list. Otherwise, we cleanly prune.
Time Complexity O(2N)

Since we have two binary choices (inclusion or exclusion) for each of the $n$ nodes, the total number of function call frames generated is $2^{n+1}-1$. Pruning allows faster results, but the raw exhaustive limit remains bounded by $O(2^N)$ binary combinations.

Space Complexity O(N)

The primary memory cost comes from the runtime activation records on the call stack. The depth of recursion is bounded strictly by $N$. Storing each valid combination of size $K$ takes linear space relative to combinations count, but extra heap space used by the backtracking stack is $O(N)$.
