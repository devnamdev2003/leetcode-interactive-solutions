Algorithm Logic & Theory

This algorithm uses a clever variation of the Sliding Window technique to solve the problem efficiently without needing extra space or complex recursion.

Core Concept:

The problem asks us to pick exactly k cards from either the beginning or the end of the array to maximize the sum. Instead of trying every combination (which would be slow), we can think of it as taking exactly k elements.

We can start by assuming we take all k elements from the left side. This forms our initial sum. Then, one by one, we "give back" an element from the right edge of our left-side selection, and "take" an element from the right side of the array.

Step-by-Step Logic:

  1. Initial Window: Calculate the sum of the first k elements. Set this as the initial maxSum.
  2. Sliding Phase: Iterate i from 0 to k-1.
    • Remove the element at cardPoints[k - 1 - i] (the rightmost selected element on the left side).
    • Add the element at cardPoints[n - 1 - i] (the rightmost unselected element on the right side).
    • Update maxSum = Math.max(maxSum, currentSum).
  3. Result: After sliding k times, we have evaluated all possible combinations of taking k cards from the ends.

Alternative Perspective: Picking k elements from the ends to maximize sum is mathematically identical to finding a continuous subarray of length n - k with the minimum sum, and subtracting that from the total sum of the array.

Time Complexity O(k)

We iterate through k elements to build the initial sum, and then we perform another loop of size k to slide the window. Thus, the time taken is directly proportional to k, regardless of how large the total array n is.

Space Complexity O(1)

The algorithm only uses a few primitive integer variables (currentSum, maxSum, n, i) to keep track of the state. We do not use any additional data structures that scale with input size.
