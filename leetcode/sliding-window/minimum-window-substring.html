Algorithm Logic & Theory

This solution utilizes the highly efficient Sliding Window technique combined with a Frequency Map to find the minimum window substring in linear time.

Core Concept: Expand and Shrink

  • Phase 1: Expand Right ($R$)
    We iterate through the string s using pointer r, expanding our "window". For every character we encounter, we decrease its required count in the frequency map. If it's a character from t that we still need (map[cr] > 0), we increment our match count.
  • Phase 2: Shrink Left ($L$)
    Once our window becomes "valid" (meaning count == t.length(), we have found all necessary characters), we stop expanding r and start shrinking the window from the left by moving pointer l.

    While shrinking, we record the minimum window size. We also restore the removed character's count in the map (map[cl]++). If restoring a character means we are now missing a required target character (map[cl] > 0), our window becomes invalid (count--), and we resume expanding r.
  • Why is the array size 128?
    ASCII characters can be directly mapped to an integer array of size 128 (or 256). Using an array int[] map instead of a Hash Map provides ultra-fast $O(1)$ lookups and updates without overhead.
Time Complexity O(N + M)

Where $N$ is the length of s and $M$ is the length of t. Initializing the map takes $O(M)$. In the worst-case scenario, both pointers $L$ and $R$ will travel across the string s exactly once. Therefore, each character is visited at most twice, yielding $O(N)$ for the sliding window phase.

Space Complexity O(1)

The space complexity is $O(1)$ constant time. Regardless of the size of the strings, the map array always consumes exactly 128 integer slots. (If using Unicode, a Hash Map might take $O(K)$ where $K$ is the unique character set, which is still bound by a constant maximum).
