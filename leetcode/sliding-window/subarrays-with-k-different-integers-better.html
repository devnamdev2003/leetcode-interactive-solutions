Algorithm Logic & Theory

Finding the exact number of subarrays with exactly K distinct integers directly is difficult because the "exact K" property isn't monotonic. A subarray might have exactly K distinct, but shrinking or expanding it might randomly break the property.

The Mathematical Trick:

exact(K) = atMost(K) - atMost(K - 1)

By calculating the number of subarrays with at most K distinct elements, and subtracting the subarrays with at most K-1 distinct elements, we isolate only the subarrays that have exactly K distinct elements.

Sliding Window (Two Pointers) logic for atMost(K):

  • Expand the Window: Use the right pointer r to add elements into our HashMap (tracking frequencies).
  • Shrink the Window (Condition Violation): If the HashMap size (distinct elements) exceeds k, we must increment the left pointer l, decrementing frequencies until the map size returns to k.
  • Count Subarrays: For a valid window [l, r], the number of valid subarrays ending at index r is exactly r - l + 1. We add this to our running total.
Time Complexity O(N)

The `atMost` function uses a sliding window where both pointers `l` and `r` only move forward. Thus, each element is added to and removed from the hash map at most once, making it strictly O(N). Since we call `atMost` twice, it's O(2N) which simplifies to O(N).

Space Complexity O(N)

We use a HashMap to store the frequency of elements within the current window. In the worst-case scenario (all elements are distinct), the map can store up to N key-value pairs, yielding O(N) extra space.
