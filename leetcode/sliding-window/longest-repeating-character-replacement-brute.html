Algorithm Logic & Theory

The provided solution utilizes a Brute-Force Sliding Window approach to find the longest substring containing the same letter after at most k replacements.

How it works:

  • Outer Loop (i): Iterates through every possible starting character in the string. It treats index i as the fixed start of a new potential window. For every new i, it resets the frequency hash array and maxj to zero.
  • Inner Loop (j): Expands the window to the right, starting from i. For each character at j, it increments its frequency in the hash array.
  • Validity Check: Inside the window `[i, j]`, it tracks maxj, which is the frequency of the most common character. The number of characters we would *need to change* to make the entire window identical is calculated as:
    ch = (Window Length) - maxj = (j - i + 1) - maxj
  • Decision: If ch <= k, the window is valid, and we potentially update our overall max length. If ch > k, the current window is invalid. Since expanding it further will only increase the length (and potentially the needed changes), the code safely breaks out of the inner loop and moves the start pointer i to the next position.

Educational Note: While this $O(N^2)$ solution works and is logically sound, an optimized $O(N)$ Sliding Window technique exists. In the optimized version, instead of resetting `i` completely, you only shrink the window from the left (`i++`) when `ch > k`, avoiding the nested loop over previously seen characters.

Time Complexity O(N²)

Where N is the length of the string. In the worst case, for every character i, the inner loop j could iterate through the rest of the string, resulting in nested loops and quadratic time complexity.

Space Complexity O(1)

The hash array always has a fixed size of 26 (to represent uppercase English letters), regardless of the size of the input string s. Therefore, the extra memory used scales constantly.
