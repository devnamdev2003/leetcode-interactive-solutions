Algorithm Logic & Theory

This solution leverages a highly optimized Sliding Window / Pointer concept to find the number of substrings containing at least one occurrence of 'a', 'b', and 'c'. Instead of generating all possible substrings (which would take $O(N^2)$ time), it tracks the most recent occurrence of each character as it iterates through the string.

Core Concept:

  • Track the Indices:
    We maintain an array lastSeen of size 3 to store the most recent index where 'a', 'b', and 'c' were seen. Initially, these are [-1, -1, -1].
  • Calculate the Bottleneck (minLastSeen):
    As we process the string at index j, we look at the minimum of the three lastSeen indices. Why? Because the character that was seen furthest in the past is our bottleneck. Any valid window ending at j must stretch far enough back to include this bottleneck character.
  • Mathematical Combination:
    If minLastSeen != -1 (meaning all three characters have appeared at least once), then a valid window exists from minLastSeen to j.
    Crucially, if the substring s[minLastSeen ... j] is valid, then any substring starting before minLastSeen and ending at j is also valid because it just includes extra characters!
    Therefore, there are exactly minLastSeen + 1 valid starting points (indices 0, 1, ..., minLastSeen). We directly add this to our total count.
Time Complexity O(N)

Where N is the length of the string. We iterate through the string exactly once. The operations inside the loop (array updates, finding the minimum of 3 elements, and addition) all take constant O(1) time.

Space Complexity O(1)

The algorithm uses an auxiliary array lastSeen of a fixed size of 3 to store character indices, plus a few integer variables. It does not scale with the size of the input string N.
