Algorithm Logic & Theory

Finding subarrays with exactly K distinct integers is difficult because the constraint isn't strictly monotonic (adding an element might increase distinct counts, but dropping an element doesn't guarantee a specific drop sequence).

The Master Trick: exact(K) = atMost(K) - atMost(K - 1)

However, finding subarrays with at most K distinct integers is completely solvable with a standard sliding window. If a window [l...r] has at most K distinct integers, then every subarray ending at r within this window (e.g., [l+1...r], [l+2...r]) also has at most K distinct integers.

Core Steps for atMost(K):

  • Expand Window: Move the right pointer r to include a new element. Increment its frequency in a map/array.
  • Track Distinct: If it's a new element (frequency was 0), increment distinctCount.
  • Shrink Window: If distinctCount > K, our window is invalid. Move the left pointer l forward, decrementing frequencies until the distinctCount drops back to K.
  • Count Valid Subarrays: For every valid window [l...r], the number of valid subarrays ending exactly at r is r - l + 1.
Time Complexity O(N)

Each element is visited at most twice per atMost() call (once by pointer r, and possibly once by pointer l). Since we call the function twice, the total passes are 4. Thus, it remains strictly $O(N)$ linear time.

Space Complexity O(N)

We use an integer array `freq` to keep track of the occurrences of numbers. In the worst case (where elements are uniquely sized up to N), the array takes $O(N)$ auxiliary space. A HashMap would also take $O(N)$ but has higher overhead.
