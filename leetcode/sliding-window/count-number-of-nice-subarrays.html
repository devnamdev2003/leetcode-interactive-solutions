Algorithm Logic & Theory

This solution cleverly transforms a problem about finding exactly $K$ occurrences into a combination of finding at most $K$ occurrences using a Sliding Window (Two Pointers) technique.

The Mathematical Trick:

Exactly(K) = AtMost(K) - AtMost(K - 1)

Calculating the number of subarrays with exactly $k$ odd numbers directly is tricky because a window might be valid, but extending it further could also keep it valid if we encounter even numbers. Instead, it's much easier to count how many subarrays have at most $k$ odd numbers. If we take all subarrays with $\le k$ odds and subtract all subarrays with $\le k-1$ odds, we are left strictly with subarrays that have exactly $k$ odds.

Sliding Window Logic (The `fun` method):

  • Pointers: Use a left pointer l and a right pointer r to represent a window [l, r].
  • Expansion: Iterate r through the array. Add the parity of nums[r] (which is `nums[r] % 2`, yielding 1 for odd, 0 for even) to a running sum. This sum tracks the number of odd elements in the current window.
  • Contraction: If sum exceeds our target limit `k`, the window is invalid. We must shrink it from the left by moving l forward and subtracting `nums[l] % 2` from sum until sum ≤ k again.
  • Counting: Once the window is valid, how many valid subarrays end at index r? The answer is exactly the size of the window: r - l + 1. We add this to our count for every step of r.
Time Complexity O(N)

The `fun` function is called twice. Inside `fun`, both the `l` and `r` pointers only move forward. `r` goes from 0 to N. The inner `while` loop advances `l`, and `l` can advance at most N times across the entire execution of the outer loop. Thus, each call to `fun` is $O(N)$. Total Time: $O(N) + O(N) = O(N)$.

Space Complexity O(1)

The algorithm only uses a few integer variables (l, r, sum, count) to keep track of the state. It does not allocate any auxiliary arrays or data structures that scale with the input size N.
