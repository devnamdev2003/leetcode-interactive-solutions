Brute Force Logic & Complexity

Note: This visualization specifically illustrates the Brute Force Approach provided in your code.

This logic simulates sweeping back and forth continuously until no changes occur. For large inputs on LeetCode, it will cause a Time Limit Exceeded or Memory Limit Exceeded. An optimal $O(M \log M)$ approach exists by sorting the restrictions, but here we focus entirely on the provided iterative sweeping method.

The Brute Force Sweep Mechanism:

  • Initialization:
    The maximum height a building `i` can reach natively (starting from height 0 at building 1 and going up by 1) is `i - 1`. We initialize an array `h` to store these maximums. Then we apply explicit restrictions by directly modifying `h[id] = min(h[id], max_height)`.
  • Constraint Propagation (The While Loop):
    Because building `i` cannot be more than 1 unit taller than `i-1` or `i+1`, any sharp drop in restriction creates a cascading ceiling across adjacent buildings. We repeatedly sweep left-to-right (`h[i] = min(h[i], h[i-1] + 1)`) and right-to-left (`h[i] = min(h[i], h[i+1] + 1)`).
  • Convergence:
    If any height is reduced during a sweep, it might affect buildings in the opposite direction. Therefore, we use a `boolean changed` flag. We keep running both sweeps in a `while(changed)` loop until a full bi-directional pass yields zero height changes.
Time Complexity O(N × Iterations)

Where $N$ is the total number of buildings. The while loop runs multiple passes. In the worst-case scenario (e.g., a steep drop restriction at the very end), the limits take many passes to fully propagate across $N$ elements, pushing time to nearly $O(N^2)$.

Space Complexity O(N)

Where $N$ is the total number of buildings. We allocate an integer array `h` of size $N + 1$ to track the state of every single building in the city.
