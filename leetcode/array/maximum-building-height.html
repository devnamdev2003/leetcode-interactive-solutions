Algorithm Logic & Theory

This solution uses a highly efficient Sweep Line / Multipass approach. The core challenge is that a building's height cannot exceed $H + |id_1 - id_2|$ where $H$ is a restricted height nearby. Because restrictions propagate in both directions, evaluating them naively is too slow.

The Multi-Pass Strategy:

  • Setup: First, ensure the mandatory base restriction at the start `(1, 0)` is present. We also inject a pseudo-restriction at the very end `(n, n-1)` to bound our calculations if the user hasn't explicitly capped the city's end. We then sort all restrictions by building ID.
  • Pass 1 (Left-to-Right):
    We iterate from left to right. A building's height is bounded by the restriction to its left. We enforce: curr_height = min(curr_height, prev_height + distance). This step ensures no restriction is violated when moving rightwards.
  • Pass 2 (Right-to-Left):
    However, a very low restriction on the right can heavily limit buildings on its left! So, we sweep backward. We enforce: curr_height = min(curr_height, next_height + distance). Now, every restriction is perfectly bounded by both its left and right neighbors.
  • Peak Finding:
    Between any two adjacent (and fully bounded) restrictions, the highest possible building occurs where the maximum possible upward slope from the left meets the maximum possible upward slope from the right.
    The math formula for this intersection is: peak = (left_height + right_height + distance) / 2. We find the maximum of these peaks across the entire city.
Time Complexity O(M log M)

Where $M$ is the number of restrictions. Sorting the restrictions array takes $O(M \log M)$ time. The subsequent sweeping passes (Left-to-Right, Right-to-Left, and Peak-Finding) are all linear $O(M)$.

Space Complexity O(M)

Where $M$ is the number of restrictions. We store them in a new List/Array to allow adding the boundary restrictions `(1, 0)` and `(n, n-1)` and to perform the sorting without mutating the original input array.
