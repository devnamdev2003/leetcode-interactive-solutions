Algorithm Logic & Theory

This solution utilizes Reverse Traversal and Lazy Propagation to optimize what would otherwise be an $O(N \times Q)$ algorithm down to $O(Q \log Q)$.

The Problem with the Naive Approach:

If we traverse queries forward, every time we encounter a Type 1 query (XOR all), we must iterate through all elements currently in our list and apply the XOR. If we have $O(Q)$ insertions and $O(Q)$ XOR operations, this results in quadratic time complexity.

The Optimal Approach (Reverse Iteration):

  • Time Travel Context
    If we process the queries from the end to the beginning (in reverse), any Type 1 XOR query we encounter represents an operation that occurred after the insertions we haven't seen yet.
  • Accumulating the Future
    We maintain a totalXor variable starting at 0. When we see a type == 1 query, we simply accumulate it: totalXor ^= val. This totalXor now holds the combined effect of all XOR operations that happen after the current point in time.
  • Applying to Insertions
    When we encounter a type == 0 query (an insertion), we know this element will be subjected to all the XOR operations we have already accumulated in our reverse traversal. So, instead of inserting the raw value, we insert val ^ totalXor.
  • The Implicit Zero
    The list implicitly starts with a 0 before any queries are run. This 0 exists for the entirety of the timeline, meaning it is affected by every single XOR query. Thus, after the loop, we add 0 ^ totalXor (which is just totalXor) to the list. Finally, we sort the list.
Time Complexity O(Q log Q)

Where $Q$ is the number of queries. The reverse traversal takes $O(Q)$ time as we process each query exactly once. The sorting step at the end dominates the time complexity taking $O(Q \log Q)$ time.

Space Complexity O(Q)

Where $Q$ is the number of queries. The space complexity is dictated by the ans list which needs to store elements. In the worst case, all queries are insertions, requiring $O(Q)$ auxiliary space.
