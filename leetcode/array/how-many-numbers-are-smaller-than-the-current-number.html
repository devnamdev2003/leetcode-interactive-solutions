Algorithm Logic & Theory

This solution uses a Counting Sort / Prefix Sum pattern, which is incredibly optimal when the constraints (maximum array values) are very small (e.g., numbers are between 0 and 100).

Core Steps:

  • Step 1: Frequency Buckets
    Instead of comparing numbers against each other in a nested loop $O(N^2)$, we use an array count of size 101. We iterate over `nums` and increment count[num]++. Now, count[X] represents exactly how many times the number $X$ appears in the input.
  • Step 2: Prefix Sum Accumulation
    This is the "Aha!" moment. If we keep a running total of frequencies as we scan the `count` array from left to right (0 to 100), the runningSum at any index $i$ is exactly the total count of numbers strictly smaller than $i$. We update count[i] = runningSum, effectively turning our frequency array into an answer lookup table.
  • Step 3: Answer Mapping
    Finally, we loop through the original `nums` array. For any nums[i], the answer is already pre-calculated inside our lookup table at count[nums[i]]. We just map it into the result array.
Time Complexity O(N + K)

Where $N$ is the length of `nums` and $K$ is the maximum possible value (here 101). Simplified to $O(N)$. We make 3 separate non-nested passes over data.

Space Complexity O(K)

Where $K$ is the constraint max value (101). The result array requires $O(N)$ space, but auxiliary space strictly for the algorithm is $O(K)$.
