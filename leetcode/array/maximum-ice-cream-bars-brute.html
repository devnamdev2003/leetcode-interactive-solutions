Algorithm Logic & Theory

The provided solution uses a Greedy / Brute Force approach to maximize the number of ice creams that can be bought with a given number of coins. It repeatedly searches the entire array to find the minimum available cost.

Note on Optimization: While this code works, scanning the array repeatedly is inefficient for large datasets. A standard optimized Greedy approach would first Sort the array ($O(N \log N)$) or use Counting Sort ($O(N+M)$) and then iterate linearly.

Core Steps Execution:

  • Step 1: Loop Pass Generation
    The outer loop i determines how many passes we make. In the worst case, we might buy all $N$ ice creams, requiring $N$ full passes.
  • Step 2: Linear Scan for Minimum
    During each pass, the inner loop j scans every element in the costs array. It ignores elements marked as -1 (already bought) and tracks the lowest price seen so far (minCost) and its location (minIndex).
  • Step 3: Verification & Purchase
    After the inner scan, it checks if it found an item (minIndex != -1) and if we have enough coins left (minCost <= coins). If we can't afford it, since we found the *absolute cheapest* item left, we know we can't afford *any* other item, so we break early.
  • Step 4: State Modification (In-Place)
    If purchased, it deducts the cost from coins, increments the count, and crucially sets costs[minIndex] = -1 to ensure this ice cream isn't picked again in the next pass.
Time Complexity O(N²)

Where $N$ is the length of the costs array. In the worst-case scenario (where we can afford every ice cream), the outer loop runs $N$ times, and for each iteration, the inner loop scans all $N$ elements, resulting in $N \times N = N^2$ operations.

Space Complexity O(1)

The algorithm uses $O(1)$ auxiliary space. It mutates the input array directly by setting bought items to -1. No additional data structures scaling with the input size are created.
