Algorithm Logic & Theory

This solution uses a Backtracking approach (Depth First Search) to explore all possible combinations of numbers that sum up to the target.

Core Steps:

  • Decision Tree Exploration:
    At every element index i, we have two primary choices:
    1. Include the element (if it doesn't exceed the remaining target k). Since we can use the same element multiple times, we stay on the same index i after including it.
    2. Exclude the element and move to the next index i + 1.
  • Backtracking:
    After fully exploring the branch where an element was included, we must "undo" our choice before returning. This is done by removing the last element from our path list v and restoring the remaining target k. This ensures a clean state for the next exploratory branch.
  • Base Cases:
    The recursion stops if we successfully reduce k to 0 (a valid combination, which we add to our answer list), or if we run out of elements (i == nums.length).
Time Complexity O(2^T)

Where T is the target value. The absolute worst case is theoretically exponential because each step can branch into including or excluding. More specifically, the depth of the recursion tree can go up to Target / Minimum Element, making the complexity loosely bounded by $O(N^{\frac{T}{min}})$.

Space Complexity O(T / min)

The space complexity is determined by the maximum depth of the recursion stack, plus the space needed for the current combination list v. The longest possible path is using the smallest element repeatedly, which is $O(\frac{Target}{min\_element})$.
