Algorithm Logic & Theory

This solution uses a Counting Sort inspired greedy approach to maximize the number of ice cream bars you can buy. Since we want the maximum quantity, we must always greedily purchase the cheapest available ice creams first.

Core Steps:

  • Step 1: Find Maximum Constraint
    To avoid standard $O(N \log N)$ sorting algorithms, we first iterate through the costs array to find the highest cost (maxCost). This allows us to size an integer frequency array optimally.
  • Step 2: Build Frequency Array
    We initialize an array freq of size maxCost + 1. By iterating through the costs array again, we use the cost itself as the index and increment its value (freq[cost]++). This records exactly how many ice creams exist at each specific price point, effectively sorting them in $O(N)$ time.
  • Step 3: Greedy Purchase
    We iterate through possible prices starting from 1 (the lowest possible cost) up to maxCost. For each price, we check if we have any ice creams available (freq[price] > 0). If we do, we calculate how many we can afford: Math.min(available_quantity, coins_left / price). We add this amount to our total count and deduct the corresponding cost from our coins. If our coins drop below the current price, we stop immediately.
Time Complexity O(N + M)

Where $N$ is the length of the costs array and $M$ is the maximum value in the array (maxCost). We iterate through the array twice $O(N)$, and then iterate up to the maximum cost $O(M)$. This is significantly faster than $O(N \log N)$ standard sorting if $M$ is reasonably bounded.

Space Complexity O(M)

Where $M$ is the maximum value in the costs array. We allocate a frequency array of size $M + 1$. This trades space for time, avoiding in-place array manipulation overhead, making it highly efficient for problems with known, reasonable upper bounds on values.
