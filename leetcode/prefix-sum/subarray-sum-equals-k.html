Algorithm Logic & Theory

This solution utilizes the Prefix Sum technique combined with a Hash Map to achieve optimal performance. A brute force approach checking all subarrays takes O(N²) time. This algorithm reduces it to O(N).

Core Concept: The Math

Let sum[i] = prefix sum up to index i.
Let sum[j] = prefix sum up to index j (where j < i).

The sum of the subarray from index (j + 1) to i is:
SubarraySum = sum[i] - sum[j]

We want to find subarrays where SubarraySum == k. Substituting this into our equation:

k = sum[i] - sum[j]
Rearranging the terms: sum[j] = sum[i] - k

Execution Steps:

  • Initialization: We store {0: 1} in our map. This handles edge cases where a prefix sum itself exactly equals k right from the start of the array.
  • Iteration: As we iterate through the array, we maintain a running total, sum.
  • The Check: At each step, we calculate target = sum - k. We check our hash map: "Have we seen a prefix sum equal to this target before?"
  • Counting: If yes, it means removing that older prefix sum from our current running sum leaves exactly k. We add the frequency of that older prefix sum to our total count (since there might be multiple ways to reach that older prefix sum due to zeroes or negative numbers).
  • Update Map: Finally, we record our current running sum into the map for future iterations to use.
Time Complexity O(N)

We traverse the array nums exactly once of length N. Inside the loop, Hash Map insertions and lookups take O(1) time on average. Thus, the overall time complexity is strictly linear.

Space Complexity O(N)

We use a Hash Map to store the frequencies of all running prefix sums. In the worst-case scenario (where all prefix sums are unique), the map will store N distinct key-value pairs, requiring linear extra space.
