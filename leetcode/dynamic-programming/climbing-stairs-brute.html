Algorithm Logic & Theory

This solution uses a Top-Down Recursive approach to solve the Climbing Stairs problem. It fundamentally reduces the problem into smaller, identical subproblems.

Core Concept:

  • The Recursive Leap of Faith
    To reach step n, you must jump from either step n-1 (a 1-step jump) or step n-2 (a 2-step jump). Therefore, the total number of unique ways to reach step n is exactly the sum of the ways to reach n-1 and n-2.
  • Overlapping Subproblems
    Notice in the recursion tree how many function calls are repeated. For example, f(4) will compute f(3) and f(2). But inside f(3), it will again compute f(2). This redundancy is what makes the naive recursive approach highly inefficient for large n.
  • Base Cases
    The recursion stops when it reaches n=1 (1 way) or n=2 (2 ways). These prevent infinite loops and provide the foundational values that bubble back up the tree.
Time Complexity O(2n)

Exponential time. Every function call branches out into exactly two more function calls. The size of the recursion tree grows exponentially as $n$ increases.

Space Complexity O(n)

Where $n$ is the target step. Even though there are $O(2^n)$ total calls, the maximum depth of the call stack (height of the recursion tree) at any given time is $n$.

Optimization Tip: Because of the overlapping subproblems, this algorithm can be optimized drastically using Memoization (caching results) or Dynamic Programming (bottom-up array), reducing the Time Complexity from $O(2^n)$ to $O(n)$.
