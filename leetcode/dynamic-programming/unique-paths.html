Math & Combinatorics Logic

This optimal solution uses pure mathematics (Combinatorics) instead of dynamic programming, changing a space-heavy grid problem into a constant space mathematical formula.

Core Concept:

  • The Path String: To go from the top-left (0,0) to the bottom-right (m-1, n-1), a robot MUST make exactly m - 1 downward moves (D) and exactly n - 1 rightward moves (R).
  • Total Steps: Regardless of the path taken, the total number of moves will always be (m - 1) + (n - 1) = m + n - 2. Think of it as constructing a string of length m + n - 2 using exactly m-1 D's and n-1 R's.
  • The Math Combination: The question "How many unique paths?" is equivalent to asking: "Out of m + n - 2 total positions in our string, how many ways can we choose m - 1 positions to place our Down moves?" (The rest will automatically be Right moves).

    This is the mathematical combination formula:
    C(TotalSteps, DownSteps) = (m + n - 2)! / ((m - 1)! * (n - 1)!)
  • Optimization (Looping Less): Because C(N, K) == C(N, N-K), we can choose to calculate permutations using the smaller dimension to save loop iterations: stepsToChoose = Math.min(m - 1, n - 1).
Time Complexity O(min(M, N))

Instead of $O(M \times N)$ required for DP, we only loop based on the smaller dimension. If M=100 and N=3, we only run the loop 2 times.

Space Complexity O(1)

We do not need an $M \times N$ matrix to cache previous results. The entire calculation is done using a few integer variables.
