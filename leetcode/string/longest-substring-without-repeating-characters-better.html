Algorithm Logic & Theory

This algorithm solves the "Longest Substring Without Repeating Characters" problem using the elegant Sliding Window technique combined with a HashSet. Instead of checking all possible substrings (which would take $O(N^3)$ or $O(N^2)$ time), this approach finds the answer in a single linear scan.

Core Concept: The Sliding Window

  • Pointers: We maintain two pointers, left and right, which represent the boundaries of our current "window" (valid substring without duplicates). Both start at index 0.
  • Expanding the Window: We slide the right pointer across the string one character at a time. We add the character at right into our HashSet to keep track of unique characters currently in our window.
  • Shrinking the Window: If we encounter a character that is already in our HashSet, we have found a duplicate! Our window is no longer valid. To fix this, we shrink the window from the left by moving the left pointer forward and removing s.charAt(left) from the HashSet. We repeat this until the duplicate is removed.
  • Tracking the Maximum: At the end of every valid window expansion, we calculate its length (right - left + 1) and update our maxLength if this new length is larger than the previous maximum.
Time Complexity O(N)

Where $N$ is the length of the string. In the worst-case scenario, each character is visited exactly twice (once by the right pointer and once by the left pointer). Thus, $2N$ operations, which simplifies to $O(N)$.

Space Complexity O(min(N, M))

Where $N$ is the length of string and $M$ is the size of the charset/alphabet. The HashSet can store at most the entire character set (e.g., 26 for English letters, 128 for ASCII). It requires $O(1)$ auxiliary space in practical competitive programming terms.
