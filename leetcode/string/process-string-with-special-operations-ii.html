Reverse Target Mapping Logic

This algorithm solves the problem of finding a character at a specific index K after generating a massive string from a set of operations. Instead of actually building the string (which could cause Memory/Time Limit Exceeded due to exponential growth from `#`), it works backwards.

Core Strategy:

  • Find Final Length: First, calculate the theoretical length of the final string. If `K` is out of bounds, instantly return '.'.
  • Trace Backwards: We iterate from the end of the operations string `s` down to `0`. At each step, we look at the operation and ask: "If my target index is currently currK, where was this target located right before this operation occurred?"
  • The Operations:
    - % (Reverse): Maps currK to the opposite side of the string. New index is prevLen - 1 - currK.
    - # (Duplicate): If the target is in the duplicated half, it mirrors the exact character in the first half. So we take the modulo: currK %= prevLen.
    - * (Delete): This deleted the character at the very end. It doesn't affect the relative indices of characters before it, so currK doesn't change.
    - Letter (Append): If a letter was appended, its index is exactly prevLen. If our currK equals prevLen, we found our target character!
Time Complexity O(N²)

Where $N$ is the length of `s`. Working backwards is $O(N)$, but the provided Java snippet calls getLength(s, i-1) inside the loop. getLength takes $O(N)$ time, resulting in $O(N^2)$ overall.

Optimization Note: It can be optimized to $O(N)$ by pre-calculating the prefix lengths into an array.

Space Complexity O(1)

The algorithm only uses a few primitive variables (i, currK, prevLen) to track the state, completely avoiding the need to store massive strings in memory. Auxiliary space is strictly $O(1)$.
