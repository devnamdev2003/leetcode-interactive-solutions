Algorithm Logic & Theory

This solution uses an Optimized Two-Step Binary Search. Because of the strict properties of the given matrix (each row is sorted, and the first element of a row is greater than the last element of the previous row), we can treat the 2D matrix almost as a single sorted 1D array, but we optimize memory access by searching in two dimensions conceptually.

Core Steps:

  • Step 1: Row Binary Search
    We initialize pointers `i` and `j` to the top and bottom rows respectively. We calculate the middle row `mid`. By examining the first element `matrix[mid][0]` and the last element `matrix[mid][m]`, we can determine if the target lies completely before this row, completely after this row, or perfectly within this row's range.
  • Step 2: Column Binary Search
    Once we confidently lock down the exact row `mid` where the target *must* reside (if it exists), we reuse the `i` and `j` pointers for the columns of that specific row. We then run a standard binary search horizontally to find the exact cell.
  • Advantage:
    This prevents having to flatten the array or use modulo arithmetic to map 1D indexes to 2D indexes, keeping the logic clean and cache-friendly.
Time Complexity O(log(R) + log(C)) = O(log(R × C))

Where $R$ is the number of rows and $C$ is the number of columns. We binary search the rows $O(\log R)$ and then binary search exactly one row $O(\log C)$.

Space Complexity O(1)

We only maintain a few integer variables (`i`, `j`, `m`, `mid`, `mid2`) for our pointers, taking up constant auxiliary space.
