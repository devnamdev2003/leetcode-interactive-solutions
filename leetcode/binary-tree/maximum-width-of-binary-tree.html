Algorithm Logic & Theory

This solution uses a Breadth-First Search (BFS) / Level-Order Traversal approach to calculate the maximum width of a binary tree. The width of one level is defined as the length between the end-nodes (the leftmost and rightmost non-null nodes in the level, where the null nodes between the end-nodes are also counted into the length calculation).

Core Concept: Index Normalization

  • Heap Indexing: We can assign an index to every node just like in a Binary Heap array representation. If a node has index i, its left child is at 2 * i + 1 and its right child is at 2 * i + 2.
  • The Overflow Problem: For highly skewed trees, this index can grow exponentially and quickly overflow standard 32-bit integers, leading to completely incorrect calculations.
  • The Solution (Normalization): At the start of each level, we find the minimum index (which is always the index of the first node in the queue for that level). For every node on that level, we calculate a normalizedIndex = current.index - minIndex. We use this normalized index to calculate the children's indices. This prevents the indices from blowing up to infinity while correctly preserving relative spacing!
  • Width Calculation: At each level, the width is simply (last - first + 1). We track the global maximum of this value across all levels.
Time Complexity O(N)

Where N is the total number of nodes in the binary tree. We visit each node exactly once during our BFS traversal. Queue operations (offer, poll) take O(1) time.

Space Complexity O(W)

Where W is the maximum width of the tree. The queue stores nodes level by level. In the worst case (a complete binary tree), the last level will have roughly N/2 nodes, making the space complexity O(N).
