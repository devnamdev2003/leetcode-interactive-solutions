Algorithm Logic & Theory

This solution effectively transforms the directed binary tree structure into an undirected graph to simulate an infection spreading radially from a starting node. It does this using a Two-Pass Breadth-First Search (BFS) approach.

Phase 1: Parent Mapping (The helper function)

Standard binary trees only have pointers downward (left, right). To spread an infection upward, we need parent pointers. The first BFS traverses the entire tree and populates a HashMap m mapping every ChildNode -> ParentNode. Simultaneously, it identifies and stores the reference to the target node (the starting point of the infection).

Phase 2: Infection Spread

The second BFS starts with the target node in a queue. It processes the tree level-by-level (representing minutes passing). For each node, it attempts to spread to:

  • Its left child (if it exists).
  • Its right child (if it exists).
  • Its parent (looked up via the HashMap m).
Clever Trick: Map as a Visited Set

To avoid infinite loops (A infects B, B infects A), we need to track visited nodes. This specific algorithm reuses the parent map m. When processing a neighbor, it checks m.containsKey(neighbor). Crucially, after a node finishes processing its neighbors, it executes m.remove(current). This removes the node from the map entirely, marking it as "visited/infected" so it won't be added to the queue again.

Time Complexity O(N)

Where N is the number of nodes in the binary tree. The first BFS (helper) visits every node exactly once to build the parent map. The second BFS visits every node at most once as the infection spreads. $O(N) + O(N) = O(N)$.

Space Complexity O(N)

The auxiliary space is dominated by the HashMap `m` which stores parent pointers for all $N$ nodes, taking $O(N)$ space. The Queue used for BFS can also hold at most $O(N)$ elements in the worst case (e.g., a completely unbalanced tree or maximum width of a balanced tree).
