Algorithm Logic & Theory

This elegant algorithm flattens a binary tree into a "linked list" structurally identical to a pre-order traversal, doing so completely in-place without creating new nodes.

The Magic of Reverse Post-Order Traversal

If we try to flatten the tree strictly from top-to-bottom (pre-order), modifying the root.right pointer overwrites the original right child before we have a chance to explore it. This typically requires an external stack or queue to keep track of lost children.

The genius of this solution is realizing that a pre-order traversal sequence generated backwards is equivalent to traversing the tree in a Right ➔ Left ➔ Root order. By processing nodes backwards, we effectively build the linked list from the tail up to the head.

Core Steps:

  • Step 1: Traverse Right Subtree
    Dive deeply into the root.right branch first until you hit a leaf.
  • Step 2: Traverse Left Subtree
    Then dive into the root.left branch.
  • Step 3: Re-wire the Pointers
    Because we traversed the right side first, our global pre pointer holds the previously processed node—which logically belongs immediately after the current root in the final flattened list.
    We set root.right = pre and clear the left pointer root.left = null.
  • Step 4: Shift the `pre` Pointer
    Finally, we update pre = root so that as the recursion bubbles up, the parent node will attach to this newly wired sub-chain.
Time Complexity O(N)

Every single node in the binary tree is visited exactly once during the recursive traversal. Work done inside the function (assigning pointers) is $O(1)$. Thus, total time scales linearly with the number of nodes $N$.

Space Complexity O(N)

Although it operates in-place on the tree's pointers (using no extra data structures like arrays or queues), it utilizes the implicit call stack for recursion. In the worst-case scenario (a skewed tree), the recursion depth reaches $N$, requiring $O(N)$ memory space. For a balanced tree, it takes $O(\log N)$ space.
