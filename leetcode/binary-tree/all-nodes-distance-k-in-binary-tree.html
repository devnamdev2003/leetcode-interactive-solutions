Algorithm Logic & Theory

Finding nodes at distance K in a binary tree requires moving both downwards (to children) and upwards (to parents). Since standard tree nodes only have pointers to children, this algorithm converts the tree into an undirected graph.

Phase 1: Map Parents (Lines 4-20)

We perform a standard Breadth-First Search (BFS) to traverse the tree. As we explore, we record each node's parent in a HashMap. The root is given a dummy parent with value -1.

Phase 2: Radial BFS from Target (Lines 22-47)

Starting from the target node, we perform a second BFS. Instead of just pushing left and right children, we push left, right, and parent into the queue, radiating outwards by 1 unit of distance per loop iteration.

Cycle Prevention

In a graph, moving back and forth between a parent and child causes an infinite loop. This algorithm cleverly uses the existing HashMap as a visited tracker. Once a node is pulled from the queue and processed, it is removed from the hash map (hash.remove(temp)). The algorithm only pushes neighbors if they still exist in the map (hash.containsKey(...)).

Time Complexity O(N)

Where N is the number of nodes in the tree. The first BFS visits every node exactly once to build the parent map. The second BFS starts from the target and radiates outwards. Because we use the map removal to prevent cycles, each node is processed at most once during the second BFS.

Space Complexity O(N)

The HashMap stores all N nodes to map their parents, taking $O(N)$ space. The Queue during either BFS can contain at most $N/2$ nodes (the width of the bottom level of a perfect binary tree), taking $O(N)$ space. Overall auxiliary space is linear.
