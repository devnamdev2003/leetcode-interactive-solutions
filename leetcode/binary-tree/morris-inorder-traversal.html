Algorithm Logic & Theory

The Morris Inorder Traversal is an ingenious algorithm that performs an inorder traversal of a binary tree in $O(N)$ time while using only $O(1)$ extra space. Traditional approaches use recursion or a stack, both of which require $O(H)$ space (where $H$ is the height of the tree) to remember the path back to the parent nodes.

Morris Traversal solves this by temporarily modifying the tree structure to establish a link (a thread) from a node's in-order predecessor directly back to the node itself. This allows the algorithm to safely navigate back up the tree without a stack.

Core Steps:

  • Case 1: No Left Child
    If the current node curr has no left child, we process curr (add to inorder list) and move to its right child.
  • Case 2: Has a Left Child
    If a left child exists, we find the inorder predecessor of curr (the rightmost node in curr's left subtree).
    • Creating a Thread: If the predecessor's right child is null, it means we haven't visited this subtree yet. We link prev.right = curr (create a thread) and move curr = curr.left.
    • Removing a Thread: If the predecessor's right child already points to curr, it means we have finished exploring the left subtree. We break the thread (prev.right = null), process curr, and move curr = curr.right.
Time Complexity O(N)

Although there is a nested while loop to find the predecessor, notice that each edge in the tree is traversed at most 3 times (once to find the predecessor, once to create the thread, and once to traverse down/remove the thread). Thus, the time complexity remains strictly linear $O(N)$.

Space Complexity O(1)

The primary advantage of Morris Traversal. It modifies the existing tree structure temporarily, using only two pointer variables (curr and prev) regardless of the tree's depth. (Note: The space required for the output array is not counted as auxiliary space).
